# Stream-server research and integration boundary

Research reviewed on **2026-09-29**.

## Catalog-provided episode links

AniList's `MediaStreamingEpisode` object provides data and links to episodes on
external streaming sites. Its `title`, `thumbnail`, `url` and `site` fields are
queried in `lib/anime/anilist.ts`, normalized into each episode, and shown under
the player as external watch links.

- AniList object reference:
  https://anilist.gitbook.io/anilist-apiv2-docs/docs/reference/object/mediastreamingepisode

These are outbound watch links, not manifests used by Aniverse's player.

## Managed-video origins

The following video-hosting services publish standard HLS URLs compatible with
this app.

### Mux Video

Mux documents HLS playback as:

```text
https://stream.mux.com/{PLAYBACK_ID}.m3u8
```

Public playback ids are stable; signed playback ids require a server-generated
token. Put stable URLs into an exact `episodes` map. Expiring signed URLs should
be generated by infrastructure you control rather than committed to JSON.

- Official guide: https://www.mux.com/docs/guides/play-your-videos

### Cloudflare Stream

Cloudflare documents HLS playback as:

```text
https://customer-{CODE}.cloudflarestream.com/{UID}/manifest/video.m3u8
```

Cloudflare also supports signed tokens and Allowed Origins. Put each video UID
(or a token generated by your own backend) into an exact episode URL.

- Official guide:
  https://developers.cloudflare.com/stream/viewing-videos/using-own-player/
- Securing playback:
  https://developers.cloudflare.com/stream/viewing-videos/securing-your-stream/

### Bunny Stream

Bunny documents its HLS storage URL as:

```text
https://{PULL_ZONE}.b-cdn.net/{VIDEO_ID}/playlist.m3u8
```

Use an exact episode map when video ids are random, or a title template if your
own ingest process assigns predictable ids.

- Official storage structure: https://bunny.net/docs/stream/storage-structure

### Self-hosted/object-storage HLS

Any public HTTPS origin works when it returns a real `#EXTM3U` manifest and its
segments/keys are reachable by the media proxy. A predictable storage layout is
the simplest option:

```text
https://media.example.com/anime/{slug}/e{episode3}/master.m3u8
```

For private origins, do not place storage credentials in browser URLs. Issue
short-lived playback URLs in trusted server infrastructure and restrict origin
access, egress and rate limits.

## Why exact episode maps were added

Managed platforms assign independent playback ids, so a URL such as
`https://stream.mux.com/{anilistId}-{episode}.m3u8` usually cannot work. The
registry now supports this production shape directly:

```json
{
  "id": "managed-library",
  "scope": "mapped",
  "episodes": {
    "anilist:21": {
      "1": "https://stream.mux.com/REAL_PLAYBACK_ID.m3u8",
      "2": "https://customer-CODE.cloudflarestream.com/REAL_UID/manifest/video.m3u8"
    }
  }
}
```

This allows arbitrary playback ids without writing a provider-specific adapter.
The static hosts of every exact URL are automatically added to the proxy
allowlist.

## Operational checklist

- Prefer adaptive HLS and include captions/audio renditions in the manifest.
- Set `ANIVERSE_ENABLE_REFERENCE_STREAMS=false` in production.
- Inspect `/api/servers`; no unexpected proxy host should be present.
- Test `/api/watch/<id>/<episode>` for several titles and episodes.
- Test child playlists, segments, keys, seeks and range requests.
- Add separate redirect/segment CDN hosts to
  `ANIVERSE_MEDIA_ALLOWED_HOSTS` only when required.
- Put rate limiting and network egress controls around `/api/proxy`.
- Do not commit signed URLs, API keys, cookies or authorization headers.
